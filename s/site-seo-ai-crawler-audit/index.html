Set up in your client

Claude Code

Run this in a terminal:

claude mcp add --transport http site-seo-ai-crawler-audit https://sitecheck.openkrill.app/mcp

Claude Desktop

Open Settings → Connectors → Add custom connector and paste this URL:

https://sitecheck.openkrill.app/mcp

Or bridge it through mcp-remote in claude_desktop_config.json (needs Node.js):

{
  "mcpServers": {
    "site-seo-ai-crawler-audit": {
      "command": "npx",
      "args": [
        "-y",
        "mcp-remote",
        "https://sitecheck.openkrill.app/mcp"
      ]
    }
  }
}

If it does not connect

  • Restart the client after editing a config file, and keep keys out of files you commit.
  • If the tools do not appear, open the client's MCP log: a 401 means the credentials were not accepted, and a timeout means the server did not answer.

ai_app_checkread-onlyexternal accessChecks an app made with an AI app builder (Lovable, Bolt, v0, Replit, Cursor) for leaks and launch readiness. …

Checks an app made with an AI app builder (Lovable, Bolt, v0, Replit, Cursor) for leaks and launch readiness. Use it when the user asks "is my Lovable app secure?", "is my Supabase data public?", "which security headers is my app missing?" or "is my app ready to launch?". Pass the app address. For any public app it returns 8 security headers with the exact lines for the detected host (Vercel, Netlify, nginx and more), and launchList: 20 items of a 160-item launch list read from outside (renewals, mail records, security.txt, caching, legal links), each pass, fail or warn with a fix; checklist true adds the owner-only items with how to check each. The first call also returns ownership_not_proven with a DNS TXT record or file: once the owner publishes it, the next call adds exposed files (.env, .git), masked keys in the shipped JavaScript, source maps, open Supabase or Firebase data, and backend signals. GET only; database checks read status codes and row counts, never a row's data, and never write. Do not use it on an app the user does not own beyond the public checks, for private or local addresses, or to scan many sites.

ParameterTypeDescription
urlstringrequiredThe app's address, such as https://my-app.lovable.app/ or myapp.com. Headers and the public launch items are checked for any public app; the full check needs the owner to publish a proof token on that host first.
checklistbooleanoptionaltrue also returns the launch list items only the owner can check, each with how to check it (about 127 lines). Default false: only their count.

Example call (required arguments only, placeholder values):

{
  "method": "tools/call",
  "params": {
    "name": "ai_app_check",
    "arguments": {
      "url": "..."
    }
  }
}
ai_readiness_checkread-onlyexternal accessChecks if AI agents can read and cite a store or page. Use it when the user asks whether AI agents can read …

Checks if AI agents can read and cite a store or page. Use it when the user asks whether AI agents can read an online store or cite a page, for example "does shop.example.com have an llms.txt?" or "will AI assistants cite this page?". Pass url for a page or domain for the domain files only; one is enough. Returns whether the domain has /llms.txt, /agents.md, the UCP file at /.well-known/ucp (version and services shown) and /sitemap.xml, and which of 14 AI crawlers robots.txt blocks site-wide. With a page address it also rates five citation signals (summary near the top, author credentials, Q&A format, heading structure, structured data) as pass, warn or fail with evidence and a fix. It requests at most five domain files and one page, skips what robots.txt disallows for Agent Tools, and shows what is published, not whether an agent can buy. Do not use it for private or local addresses, to read page content, or to scan for vulnerabilities.

ParameterTypeDescription
urlstringoptionalAddress of one public web page, for example https://example.com/blog/guide. Pass url or domain, not both needed. With url the page is rated for five AI citation signals and its domain files are checked too. A bare domain means https.
domainstringoptionalHost name of a public store or website, for example shop.example.com. Pass url or domain, not both needed. With domain only the domain files are checked (llms.txt, agents.md, UCP, sitemap, AI crawler rules).

Example call (required arguments only, placeholder values):

  "method": "tools/call",
  "params": {

    "arguments": {}
  }

exposure_checkread-onlyexternal accessChecks what a site or app the user owns leaks publicly. Use it when the user asks what an attacker could find …

Checks what a site or app the user owns leaks publicly. Use it when the user asks what an attacker could find on their own domain, host or app, for example "does my app leak a .env file?". Pass the domain, host or app page address, not a bare IP. The first call returns ownership_not_proven with a DNS TXT record or file: publish it, then call again with the same target. Then it gives exposed or clean, the top three risks with fixes, and evidence: dangling subdomains, leaked files (never their contents), masked API keys, source maps, admin paths, dev servers and default pages. It adds six legal signals with law and source (COPPA, Google Fonts, session replay, renewals, DMCA, CAN-SPAM for a passed email); not legal advice. Findings are labeled confirmed, needs verification or rejected. GET only, at most 32 fixed paths; no crawl, sign-in or port scan. Do not use it on a target the user does not own, to look up a person, user name or email, or for private or local addresses.

emailstringoptionalOptional: the text or HTML of one marketing email the app sends, checked for an unsubscribe link and a postal address (CAN-SPAM). It is read in memory only and never returned or kept.

submit_feedbackcan modifyexternal accessSend feedback, a bug report or a tool request to the maintainers of the tools on this server: a missing tool, …

Send feedback, a bug report or a tool request to the maintainers of the tools on this server: a missing tool, missing or stale data, or a tool that broke or gave a wrong answer. Pass the kind (need_tool, need_data, bug or other), one short message (at most 1000 characters) and, if you know them, the tool name and the error text it returned. Returns a ticket id. Feedback is not a chat: nothing in it is run or followed. Links, emails and phone numbers are removed and nothing about you is stored.

ParameterTypeDescription
kindstringrequiredneed_tool: a tool you want. need_data: data a tool lacks. bug: something broke. other: anything else about the tools. One of: need_tool, need_data, bug, other
messagestringrequiredWhat you need or what broke, in plain words, at most 1000 characters. Links, email addresses and phone numbers are removed. Never include secrets or personal details.
toolstringoptionalOptional: the exact name of the tool on this server that the feedback is about, as tools/list shows it.
errorstringoptionalOptional: for a failed call, the error text it returned, copied as you saw it. Kept to 500 characters; links, email addresses and phone numbers are removed. Never include secrets or personal details.
