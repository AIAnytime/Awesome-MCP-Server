Set up in your client

Claude Code

Run this in a terminal:

claude mcp add --transport http twitterapi-io https://mcp.twitterapi.io/mcp

Claude Desktop

Open Settings → Connectors → Add custom connector and paste this URL:

https://mcp.twitterapi.io/mcp

Or bridge it through mcp-remote in claude_desktop_config.json (needs Node.js):

{
  "mcpServers": {
    "twitterapi-io": {
      "command": "npx",
      "args": [
        "-y",
        "mcp-remote",
        "https://mcp.twitterapi.io/mcp"
      ]
    }
  }
}

Cursor

Add to Cursor

Or add it to ~/.cursor/mcp.json (or .cursor/mcp.json in a project):

{
  "mcpServers": {
    "twitterapi-io": {
      "url": "https://mcp.twitterapi.io/mcp"
    }
  }
}

VS Code

Add to VS Code

Or add it to .vscode/mcp.json:

{
  "servers": {
    "twitterapi-io": {
      "type": "http",
      "url": "https://mcp.twitterapi.io/mcp"
    }
  }
}

Or from a terminal:

code --add-mcp '{"name": "twitterapi-io", "type": "http", "url": "https://mcp.twitterapi.io/mcp"}'

Windsurf

Add it to ~/.codeium/windsurf/mcp_config.json:

{
  "mcpServers": {
    "twitterapi-io": {
      "serverUrl": "https://mcp.twitterapi.io/mcp"
    }
  }
}

If it does not connect

  • Restart the client after editing a config file, and keep keys out of files you commit.
  • If the tools do not appear, open the client's MCP log: a 401 means the credentials were not accepted, and a timeout means the server did not answer.

search_tweetsread-onlyexternal access🎯 PRIMARY CHOICE for date-range / historical / keyword-based tweet queries. Use this (NOT …

🎯 PRIMARY CHOICE for date-range / historical / keyword-based tweet queries. Use this (NOT get_user_last_tweets) whenever user asks about a SPECIFIC TIME RANGE or historical tweets: • 'tweets from January 2026' → query='from:elonmusk since:2026-01-01 until:2026-02-01' • 'tweets between X and Y' → 'from:USER since:X until:Y' • 'tweets last week / last month' → translate to since:/until: dates • 'tweets containing keyword X by user Y' → 'from:Y X' • 'older tweets' / 'archive' / 'in 2025' → use date range, not pagination Date format: YYYY-MM-DD (UTC midnight). 'until:' is exclusive (until:2026-02-01 = up to Jan 31). General: Search Twitter/X for tweets matching a query. Supports the full Twitter advanced search syntax (from:, to:, since:, until:, lang:, filter:, has:, -, OR, etc). Returns ~20 tweets per page in reverse chronological order ('Latest') or by engagement ('Top'). Use this for keyword research, monitoring mentions of a brand/topic, finding tweets in a date range, or any open-ended tweet discovery.

ParameterTypeDescription
querystringrequiredTwitter advanced search query string. Supports operators: from:USER, to:USER, since:YYYY-MM-DD, until:YYYY-MM-DD, lang:en, filter:replies, -filter:retweets, has:images, etc. Example: 'from:elonmusk since:2026-01-01 has:images'
queryTypestringrequired'Latest' returns most recent tweets first; 'Top' returns highest-engagement tweets first. Default to 'Latest' for time-sensitive queries. One of: Latest, Top
cursorstringoptionalPagination cursor from a previous response's next_cursor field. Omit for first page. Each page returns ~20 tweets.

Example call (required arguments only, placeholder values):

{
  "method": "tools/call",
  "params": {
    "name": "search_tweets",
    "arguments": {
      "query": "...",
      "queryType": "Latest"
    }
  }
}
